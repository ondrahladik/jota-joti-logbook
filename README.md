# JOTA-JOTI Logbook

Open-source web application for amateur radio clubs participating in the annual **JOTA-JOTI** (Jamboree on the Air / Jamboree on the Internet) event organized by the World Scout Bureau.

## Features

- **QSO Logbook** - log radio contacts per year, one logbook per event year; multiple years supported simultaneously
- **Add / Edit / Delete QSO** - full CRUD with form validation; band is required
- **Fulltext search** - live filter across all QSO fields with record count indicator
- **ADIF export** - standard `.adi` file compatible with all logging software
- **XLSX export** - native Excel spreadsheet export (no Excel required on server)
- **Statistics** - per-logbook QSO count shown on dashboard
- **Multi-language** - 20 languages: English, Czech, German, Slovak, French, Spanish, Italian, Portuguese, Polish, Russian, Ukrainian, Turkish, Indonesian, Dutch, Swedish, Norwegian, Danish, Japanese, Korean, Hungarian
- **Light / Dark mode** - user selectable, configurable default in setup
- **Role-based access** - Guest (read-only), User (full logbook), Admin (everything + config)
- **Setup wizard** - 3-step first-run wizard; no manual file editing required
- **Web configuration** - admin UI to change all settings without touching files
- **Pretty URLs** - `/logbook`, `/login`, `/help`, `/config`, `/setup`
- **Custom error pages** - themed 400, 403, 404, 500 and DB/PHP error pages
- **Toast notifications** - non-blocking success/error/warning messages
- **CSRF protection** - all forms include CSRF tokens
- **Responsive design** - Bootstrap 5 based, works on mobile and desktop

## Installation

1. **Clone or download** the repository into your web root:
   ```bash
   git clone https://github.com/ondrahladik/jota-joti-logbook.git
   cd jota-joti-logbook
   ```

2. **Apache setup** - make sure `mod_rewrite` is enabled and `AllowOverride All` is set for the directory.

3. **Open the app** in your browser. If not yet configured, the setup wizard starts automatically.

4. **Follow the 3-step wizard:**
   | Step | What you configure |
   |------|--------------------|
   | 1 | Language, theme, callsign, application name |
   | 2 | Database connection (validated before proceeding) |
   | 3 | Admin password, user password |

5. After setup the application is ready. The wizard will not run again.

## Configuration

All settings are stored in `config/settings.php` (auto-generated by the wizard).  
This file is listed in `.gitignore` - your credentials are **never committed**.

| File | Purpose |
|------|---------|
| `config/settings.php` | Active configuration (gitignored) |
| `config/settings.example.php` | Template showing all available keys |
| `config/installed.lock` | Presence of this file prevents the wizard from re-running |

> To re-run the setup wizard, delete `config/installed.lock`.

After installation you can change all settings via the **Config** page (Admin only) at `/config`.

## User Roles

| Role | View logbook | Add / Edit / Delete QSO | Create / Delete logbooks | Config |
|------|:---:|:---:|:---:|:---:|
| Guest | Yes | No | No | No |
| User | Yes | Yes (current year) | No | No |
| Admin | Yes | Yes (all years) | Yes | Yes |

- Roles are unlocked by password entered on the **Login** page.
- Leave the user password empty in config to disable that role (guests only).
- Passwords are stored as **bcrypt hashes** - plain-text passwords are never saved.

## Database Structure

The application manages its own schema. No manual SQL is required.

| Table | Description |
|-------|-------------|
| `logbooks` | Registry of all event years (year, callsign, notes, created_at) |
| `log_YYYY` | One table per year with individual QSO records |

QSO record fields: `callsign`, `band`, `mode`, `qth`, `locator`, `rst_tx`, `rst_rx`, `scout_name`, `note`, `qso_time`, `created_at`.

## Security Notes

- `config/settings.php` and `config/installed.lock` are in `.gitignore` - credentials are never committed to the repository.
- The `config/` directory has its own `.htaccess` denying direct HTTP access.
- All passwords are stored as **bcrypt hashes** (`password_hash` / `password_verify`).
- All POST forms are protected with **CSRF tokens**.
- User input is escaped with `htmlspecialchars` / `mysqli` prepared statements.
